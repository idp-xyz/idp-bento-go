# 写给 Agent 读的文档

skill、`AGENTS.md`、`.cursor/rules/*.mdc`、被指针引到的参考文档——封装形式不同，写法是同一套。目标是让 agent **每次都走同一个流程**，而不是每次都产出同一段文字。

## 两种预算

每加一份文档、每加一条指针，都在花下面两种预算之一。

**上下文预算**是常驻材料压在窗口上的成本：一行 `AGENTS.md`、一句 skill description、任何每轮都在场的东西，不管它这轮有没有派上用场，token 和注意力都照付。

**认知预算**是压在人身上的成本：有哪些文档存在、什么时候该找哪一份。人就是那个索引。这份成本不该一味压缩——它是人保有主导权的价钱。该花在需要人判断的地方，该省在不需要的地方。

只通过指针才能到达的材料，用一行指针的代价换掉了自己的上下文预算；完全没有指针的材料，则整个骑在认知预算上。

## 信息阶梯

文档由两类内容构成：**步骤**（agent 按顺序执行的动作）和**参考**（按需查阅的定义、规则、事实）。两者可以自由混合——全是步骤（一份配方）、全是参考（一份评审规则、本文）、或者两者兼有。

核心决定是每块内容坐在阶梯的哪一级，排序依据是 agent 需要它的紧迫程度：

1. **文件内步骤**——首要层级，agent 要做什么，按顺序。
2. **文件内参考**——按需查阅。经常是一组扁平的同级项（一次评审的所有规则平铺在同一级），这是合理布局，不是坏味道。
3. **外置参考**——推到独立文件，靠指针到达，指针触发时才加载。

往下推得太少，顶层臃肿；推得太多，agent 真正需要的东西被藏起来。这个张力就是全部的决定。

**渐进披露**是往下挪的动作——移出主文件、放到指针后面，让顶层保持可读。它首先不是省 token，而是保护阶梯本身。最干净的判据是分支：每个分支都需要的内联，只有部分分支会到达的推到指针后面。当文档里有步骤时，本该外置的文件内参考会把步骤埋掉，让 agent 是否留意到它们变成抛硬币。

**就近归置**是文件内的配套动作：阶梯决定一块内容坐多低，就近归置决定它坐下来之后旁边是谁。把一个概念的定义、规则、注意事项放在同一个标题下，读到其中一部分就会连带看到邻居。检验方法是通读——归置好的材料读起来像是为 agent 写的说明书，散落的不像。

**蔓延**是这里的失败模式：文档单纯就是太长了，哪怕每一行都还活着、都不重复。注意力在多余的篇幅里被稀释，而且每多一行就多一行要维持相关性。解法就是阶梯：把参考披露到指针后面，按分支或按顺序拆开，让每条路径只携带它需要的东西。

## 上下文指针

**上下文指针**是常驻在上下文里的一句引用，它点名某份不在上下文里的材料，并编码了到达那份材料的条件。skill 的 description 是一个指针，`AGENTS.md` 里点名某份文档的那一行是同一种东西。

决定 agent 何时到达、以及到达得多可靠的，是**指针的措辞**，不是目标本身。一份必读的材料配一句措辞含糊的指针，那是个方差 bug——先把措辞磨锋利，磨不动了再考虑把材料内联进来。

指针干两件事：说清材料是什么，列出应该触发到达的**分支**。常驻指针的每个词每轮都在收费，所以它比正文更该被狠剪：

- **把引导词前置**——指针正是它发挥触发作用的地方。
- **一个分支一个触发词**。给同一个分支起两个名字的近义词是把一个分支写了两遍，合并掉，只留真正不同的分支。
- **删掉正文已经承载的身份信息**。

## 步骤与完成判据

每个步骤都终结于一条**完成判据**——告诉 agent 这件事做完了的条件。两个属性决定它好不好用。

**清晰度**：agent 分得清"做完了"和"没做完"吗？含糊的边界（"达成了理解"）会招来**过早收工**——在真正做完之前就结束，注意力滑向"我完成了"。后面还看得见的步骤会产生这股拉力，判据的清晰度就是阻力。先磨锋利边界，这是局部且便宜的；只有当边界确实无法再精确、而且你真的观察到了赶工，才考虑把后续步骤拆出视野。

**要求量**：判据要求多少工作。"每一个被修改的模型都有交代"会逼出扎实的活，"产出一份变更清单"不会。要求量驱动**跑腿量**——agent 在工作内部做的挖掘，它潜伏在措辞里而不是写成独立步骤。它也不绑定步骤："每一条规则都已应用"约束一堆扁平参考的力度，和"每一步都已完成"约束一段流程是一样的。

最强的判据同时可核对且穷尽。

## 引导词

**引导词**是一个已经存在于模型预训练里的紧凑概念，agent 在执行文档时用它来思考。把它作为一个词反复出现（而不是反复解释同一个意思），它会累积出分布式的定义，用最少的 token 锚定一整片行为区域。

自己造词也能用，但造出来的词招不来任何先验——你得用定义 token 去买一个现成词免费给你的东西。先找现成的。

它锚定两次。在正文里锚定**执行**：这个词每次出现，agent 都伸手去拿同一套行为。在指针里锚定**触发**：当同一个词同时活在你的提示、你的文档和你的代码里，agent 会把这套共享语言和材料关联起来，到达得更可靠。

主动去找可以用引导词收拢的地方。一个在三处分别展开的三元组、一句花了整段去比划一个意思的指针，都是在求着被收成一个词。假设每份文档都藏着可以被引导词退休掉的重复表述，去找出来。

## 正向表述

用禁令来引导是失败模式：被禁的行为会因此被拖进上下文，变得**更容易**被激活。说"别想大象"，满脑子就只剩大象——否定词是个弱修饰符，会被强激活的概念冲垮，禁令有一半读起来像是在教你做那件事。

正确做法是把目标行为正面说出来，让不想要的那个词根本不出现。"写单行注释"胜过"不要写多行注释"。

禁令只在一种情况下值得留：它是一条你实在无法正面表述的硬护栏。即便如此，也要同时给出正面目标，让注意力落在该做什么上。

## 修剪

**单一事实来源**：一个意思只在一个权威位置存在，改行为时只改一处。同一个意思出现在多处，既要付维护和 token 成本，还会把这个意思在阶梯上的显要程度抬高到超过它的真实排位。（这是引导词的反面：引导词故意重复同一个**词**，从不重复同一个**意思**。）

**环境也是事实来源**：`go.mod`、目录结构、CI 配置、`--help` 输出。复述环境的文档只是一份**缓存**，只有当那次查找很贵时才配得上它占的位置。该缓存的是 agent 查不到的东西——不成文的约定、某个选择背后的理由、配置文件不会承认的坑。一个文件一条命令就能查到的，留给环境，那里不会过期。

**相关性**：逐行检查，这行还关系到文档要做的事吗？一行会因为从来不影响任务而失去相关性（纯铺陈，或者一个本该被披露出去的分支），也会因为它描述的行为或世界变了而变陈旧。缺少修剪纪律时，默认结局是**沉积**：因为添加感觉安全、删除感觉危险，陈旧的层一层层落下来，直到你必须打钻才能找到还活着的部分。

**猎杀空转**：逐句问，模型默认就会照做的指令，是在花成本说废话。检验标准是"它相对默认行为改变了什么"，这是相对模型而言、不是相对读者而言的——两个人对某句是不是空转有分歧，说明他们对默认行为的判断有分歧，靠跑一遍来定，不靠争论。一句话没通过检验就整句删掉，而不是从里面抠字。这条标准也给引导词打分：一个弱到打不过默认行为的词（agent 本来就还算周全，你写"要周全"）就是空转，修法是换个更强的词，不是换个技术。
