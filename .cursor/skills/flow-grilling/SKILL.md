# Grilling

在做出重要决定之前，把用户逼问到双方达成共识，并在共识成形的当下就把术语和决定写进文档。共识达成之后再开始实现。

## 先读仓库画像

`.cursor/repo-profile.md` 声明本仓库的术语表路径、ADR 目录与格式、以及硬边界。开始之前先读它。

画像不存在时，先用一轮 grilling 把这些问清楚——术语表放哪、ADR 放哪、用什么结构、有没有索引要维护、有哪些所有权边界——写成 `.cursor/repo-profile.md`，再继续正题。

## 访谈循环

把整件事画成一棵**决策树**：每个决定都会分叉出挂在它下面的决定。

**frontier** 是所有前置条件已经确定的决定——此刻就能问、不需要猜测未知答案的问题。按**轮次**推进：每轮把整个 frontier 一次问完，用户回答后重算 frontier，进入下一轮。一个答案依赖于本轮其它未决问题的问题，属于后面的轮次。

每个问题按这个格式呈现：

```
❓ **Q1** - **<问题标题>**：<问题正文，可以多段，可以给选项>

➡️ <你推荐的答案>
```

每个问题都带上你推荐的答案。省掉推荐等于把思考成本推回给用户。

用户每轮的回答会重塑这棵树——已确定的决定把 frontier 向外推，解锁原先被它挡住的问题。frontier 空了，也就是决策树每个分支都走过、没有任何东西被默默假设，本轮才结束。

## 事实自己查，决定归用户

能从环境里查到的**事实**（文件系统、代码、Git 历史、依赖、CI 配置）是你的活，在当前会话内直接查完。**决定**是用户的，逐个抛给他，等他回答。

查证会占用轮次时间，所以先把不依赖查证的 frontier 问题发出去，让查证和问答并行推进。

本工作区禁止并发 subagent 任务，这条是硬护栏：所有查证在当前会话内完成。

## 术语当场落表

用户用的词一旦出现歧义或和既有术语冲突，当场提出来。

- **挑战既有术语**：用户用的词和术语表里的定义冲突时立刻指出——"术语表把 X 定义成 A，你这里像是在说 B，到底是哪个？"
- **收紧模糊表达**：遇到含糊或一词多义的说法，提出一个精确的规范用词。
- **用具体场景压测**：讨论概念之间的关系时，编造能触到边界的场景，逼用户把界限说清楚。
- **和代码对照**：用户描述某个机制的工作方式时，去代码里核对。发现矛盾就摆出来。

术语一敲定就当场写进画像指定的术语表，用画像给的条目格式。只收本仓库自己的术语——通用编程概念（超时、错误类型、工具模式）留在外面。

## ADR 只留三条都满足的

**同时满足三条**才提议写 ADR：

1. **难以逆转**——以后改主意的代价是实打实的
2. **没有上下文会让人困惑**——将来的读者会问"当初为什么这么干"
3. **是真实取舍的结果**——存在过真正的替代方案，你为了具体理由选了其中一个

缺任何一条就跳过。三条都满足时，按画像给的目录、编号规则、结构模板和索引维护要求落笔。

## 边界

画像的「硬边界」一节列出了本仓库的所有权边界和排除项，全程遵守。
