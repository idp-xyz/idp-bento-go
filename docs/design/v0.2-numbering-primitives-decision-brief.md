# `v0.2` 编号原语决策简报

状态：已取代（2026-08-24）— 编号原语随 `idp-platform-go` 立库整体转移，见 [ADR-0011](../adr/0011-numbering-primitives-move-to-platform-go.md)；本文保留作历史记录，其中双消费者用例确认与 Python 兼容约束由 `idp-platform-go` 立库简报承接

日期：2026-08-24

## 目标

把 2026-08-24 grilling 达成的共识固化为 `v0.2` 提案入口：框架接收业务无关的**编号原语**，**平台能力**保持在框架之外。本文不把任何尚未创建的代码、迁移或测试描述为已实现能力。

边界决定本身已被接受并记录于 [ADR-0010](../adr/0010-numbering-primitives-platform-boundary.md)；本简报承载其中可实施的 `v0.2` 部分和尚未绑定的前提。

## 已确认决定

| 议题 | 结论 |
| --- | --- |
| 编号模板 DSL 落点 | `idp-bento-go` 新核心包，纯标准库 |
| Feistel 加扰与校验位落点 | 同包；密钥由消费者持有并通过参数传入，框架不管理凭据 |
| 原子序列分配落点 | `postgres/sequence` 实验性适配器 + 一张序列技术表 |
| 能力层（选项目录、单据类型目录、预留/认领） | 永不进入框架；去处 `UNBOUND` |
| 包名 | `numbering` |
| 稳定性分级 | 引入即 `EXPERIMENTAL`；双消费者真实切片验证后方可在后续 minor 升稳定核心 |
| 与 Python 的兼容契约 | 令牌词汇表语义兼容；不承诺 API 形状对等或加扰/校验位输出逐位相等 |
| 实现时机 | `v0.1.0` 稳定发布之后 |
| 立项证据 | TMS 与 Parcel 各书面确认一个编号用例，不要求先有代码 |

## 范围

### 进入框架

`numbering`（新核心包，纯标准库，`EXPERIMENTAL`）：

- 编号模板 DSL：`{type}`、日期令牌 `{yyyy}`/`{yy}`/`{q}`/`{mm}`/`{dd}`、时间令牌 `{hh}{mi}{ss}{ms}`、序列 `{seq[:N]}`/`{seq36}`、加扰序列 `{seqx}`/`{seqx36}`、`{rand}`、校验位 `{check}`。精确令牌集与解析/渲染 API 形状在实现阶段确定，词汇表以与 Python `FormatTemplate` 语义兼容为约束。
- 重置粒度由模板中最细日期令牌推导（连续 → 年 → 季 → 月 → 日）。
- Feistel FPE 加扰与校验位算法。

`postgres/sequence`（实验性适配器）：

- 一张序列技术表 + 单条条件 SQL 的原子分配；不先读后写。
- 框架拥有不可变迁移资产（追加新迁移 ID，不改已发布迁移），消费者拥有迁移执行、权限和历史。
- `UNBOUND`：具体表 DDL、迁移 ID、索引与专用 schema 细节，实现阶段出专项简报或并入本简报修订。

### 明确排除（永不进入框架，ADR-0010）

- 选项目录能力全部：`Option`/`OptionDetail` 聚合、作用域继承、变更审计、管理 API。
- 单据类型目录（`DocTypeSpec` registry、DB overlay）。
- 编号预留/认领、草稿持有 TTL、外部编号强制。
- DTO、requests/responses、HTTP 路由工厂。

排除项去处 `UNBOUND`：独立 `idp-platform-go` 库或消费者仓库，等真实重复出现后另行决策；不在本简报内解决。

## 兼容性契约

- `numbering` 与 `postgres/sequence` 进入 `api/packages.json` 与逐包 apidiff snapshot，标记 `EXPERIMENTAL`。
- 模板令牌词汇表是跨生态可迁移的配置数据；API 形状按 Go 惯例自由设计。
- 不承诺加扰或校验位与 Python 实现输出逐位相等；未来任何跨语言数据迁移需自行换算。

## 依赖规则

- `numbering` 只依赖 Go 标准库；`domain`、`repository`、`eventing`、`application` 不反向依赖 `numbering`。
- `postgres/sequence` 依赖父级 `postgres`，可实现 `numbering` 定义的序列端口；核心不反向导入适配器。
- `dependencycheck` 扩展覆盖新包，维持既有负向门禁（生产依赖图禁 `testkit`、核心禁 PostgreSQL 反向依赖）。

## 兼容性制品扩展方案（已评审通过，2026-08-24）

- `api/packages.json` 追加 `numbering` 与 `postgres/sequence`，均标 `EXPERIMENTAL`。
- 为两个新包生成无本机绝对路径的逐包 `.apidiff` snapshot；与上一发布版本比较的基线规则不变，不得以更新当前 snapshot 代替历史比较。
- 核心编译夹具扩展覆盖 `numbering` 全部公共符号；PostgreSQL 编译夹具覆盖 `postgres/sequence`。
- 模板渲染引入版本化行为清单（对齐 Envelope 行为清单模式）：令牌集、重置粒度推导、加扰与校验位的确定性输出用例；清单版本独立于 Envelope `SpecVersion`。
- `dependencycheck` 新增规则：`numbering` 只依赖标准库；`domain`、`repository`、`eventing`、`application` 不得导入 `numbering`（核心包保持互不依赖）；`postgres/sequence` 只可依赖父级 `postgres` 与 `numbering`；`postgres/outbox`、`postgres/inbox`、`postgres/sequence` 互不导入。
- `candidatecheck` 的既有测试与门禁自动覆盖新包，不新增入口。

## 确认前提（Draft → 已确认的门禁）

1. `v0.1.0` 稳定发布完成（`B-04` 至 `B-06` 绑定、受保护 CI 与双消费者正式合同证明）。
2. 已确认（2026-08-24，维护者书面确认）：TMS 用例为运输任务业务编号 `execution.transport_task.reference`——单据类型运输任务，格式样例 `TT-2026-0001`（模板 `TT-{yyyy}-{seq:4}`），按年重置。代码证据：生产 schema 中字段 `NOT NULL`，测试夹具已使用该形态，生成逻辑缺失。
3. 已确认（2026-08-24，维护者书面确认）：Parcel 用例为结算对账单号——单据类型对账单（`settlement-accounting` 上下文要求发布时固定单号、作废后新单不复用原身份），格式样例 `STMT-202608-00001`（模板 `STMT-{yyyy}{mm}-{seq:5}`），按月重置；前缀与位数可由 Parcel 侧在实现前调整，不影响立项。包裹运单号/追踪号不作候选：按 Parcel 领域语言它们是外部标识，由外部参与方分配。
4. 已确认（2026-08-24）：兼容性制品扩展方案（见上节）经维护者评审通过。

## 非目标

- 不移植 AutoMapper、RepositoryAdapter、CQRS 基类等 Python bento 其余部分。
- 不提供编号的 HTTP API 或管理界面。
- 不在框架内管理加扰密钥或任何凭据。
- 不提供跨语言编号互认或号段迁移工具。
