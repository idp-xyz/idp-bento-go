状态：已确认

日期：2026-07-29

## 目标

把已经确认的 `R-01` 至 `R-06`、正式 Go module path、实施顺序、兼容性制品和发布门禁汇总为一份开发交接入口。本文确认的是可实施设计，不把尚未创建的代码、迁移、测试或 CI 描述为已实现能力。

本文已经获得最终确认，授权创建本地 `go.mod`、源码脚手架、兼容性制品和实施任务；实际 Git 仓库和 module 解析合同已经绑定，DNS、TLS、metadata 解析部署和 `v0.1.0-rc.1` 的空缓存真实获取已经验证，其他远端资源、双消费者证明与受保护发布候选仍受对应外部门禁约束。

## 最终设计门禁

| ID | 已确认合同 | 权威文档 | 实现不得重新选择 |
| --- | --- | --- | --- |
| `R-01` | 最小领域事件原语与 `EventBuffer` | [domain 公共合同](./domain-contract.md) | 不增加 Aggregate、Entity、Value Object 基类或通用领域错误 |
| `R-02` | Handler、Clock、IDGenerator、Required Transactor、rollback-only 与提交不确定语义 | [application 与事务合同](./application-transaction-contract.md) | 不增加 Bus、Repository Registry、RequiresNew、保存点或自动重试 |
| `R-03` | 版本化 Envelope、Publisher、按分区有序 At-Least-Once Outbox 与事务性 Inbox | [eventing 合同](./eventing-contract.md) | 不声称 Exactly-Once，不引入开放元数据或通用消息路由 |
| `R-04` | `pgx/v5` 事务绑定、三表 DDL、并发 SQL、迁移渲染与只读 `CheckSchema` | [PostgreSQL 适配器合同](./postgres-adapter-contract.md) | 不引入 ORM、通用业务 Repository、自动迁移或运行策略所有权 |
| `R-05` | 确定性替身与工厂驱动真实端口的合同运行器 | [testkit 公共合同](./testkit-contract.md) | 不增加通用内存 Repository、Fake Transactor 或公共 PostgreSQL 夹具 |
| `R-06` | apidiff、编译夹具、版本化行为清单和双消费者合同四层兼容性门禁 | [公共 API 与行为兼容性合同](./public-api-compatibility-contract.md) | 不以更新当前 snapshot 代替上一发布版本比较 |

`R-01` 至 `R-06` 均为 `CONFIRMED`。开发任务只实现这些合同，不得借实现便利扩大公共 API、改变消费者所有权或把 TMS/Parcel 业务语义带入框架。

## 包与依赖基线

正式公共导入以 `go.idp.xyz/idp-bento-go` 为根：

```text
go.idp.xyz/idp-bento-go/domain
go.idp.xyz/idp-bento-go/repository
go.idp.xyz/idp-bento-go/eventing
go.idp.xyz/idp-bento-go/application
go.idp.xyz/idp-bento-go/testkit
go.idp.xyz/idp-bento-go/postgres
go.idp.xyz/idp-bento-go/postgres/outbox
go.idp.xyz/idp-bento-go/postgres/inbox
```

- `domain`、`repository`、`eventing` 只依赖 Go 标准库。
- `application` 只依赖标准库与公共核心，不依赖适配器。
- `testkit` 只依赖标准库与公共核心，生产依赖图禁止导入。
- `postgres` 及子包是 `v0.x` 实验性适配器；核心不得反向依赖。
- `postgres/outbox` 与 `postgres/inbox` 不互相导入，也不导入消费者。
- 公共符号采用 allowlist；未列出的符号默认保持未导出或位于 `internal`。

## 实施顺序

### 1. 建立可复现基线

- 创建 `go.mod`，module 必须精确为 `go.idp.xyz/idp-bento-go`。
- `B-02` 已锁定 Go 工具链 `1.26.5`、`pgx/v5 v5.10.0`、OpenTelemetry API `v1.44.0`、`x/exp v0.0.0-20260727155853-b88d891fe743` 与 `x/mod v0.38.0`。`x/exp` 提供 apidiff，`x/mod/semver` 校验候选版本；checksum 由 `go.sum` 固定。
- 创建包目录、`internal` 边界、架构依赖负向测试和文档检查，不先创建宽泛辅助包。

### 2. 实现稳定核心

- 按 `R-01` 实现 `domain`。
- 按 Repository 小能力接口、错误分类和 `Revision` 合同实现 `repository`。
- 按 `R-03` 先实现与数据库无关的 `eventing` 类型、校验和端口。
- 按 `R-02` 实现 `application`；事务端口保持驱动无关，提交不确定不得被误判为回滚。

每完成一个包，立即生成其公共 API snapshot、编译夹具和负向测试，禁止在所有实现完成后再追认公共面。

### 3. 实现 testkit 与兼容性基线

- 实现 `FixedClock`、`SequenceIDGenerator`、`RecordingPublisher`、`ValidEnvelope` 和三个合同运行器。
- 创建初始 packages manifest、逐包 snapshots、Envelope V1 行为清单和核心编译夹具。
- 证明 `testkit` 不进入生产依赖图，历史 SpecVersion 夹具不可被当前版本替换。

### 4. 实现 PostgreSQL 基础适配器

- 实现私有事务 carrier、DB、窄化 Querier/Executor、迁移清单、受控 schema 渲染和只读 `CheckSchema`。
- 写参与者缺少事务时必须返回 `ErrTransactionRequired`；读取路径必须显式选择 ReadExecutor 或 RequireExecutor。
- 消费者仍拥有业务 Repository、显式 SQL、迁移执行和生产编排。

### 5. 实现 Outbox/Inbox Store 并执行 `I-04`

- 按已确认 DDL、READ COMMITTED、advisory lock、行锁顺序和有界条件更新实现真实 Store。
- 用真实迁移、`CheckSchema` 和 Store 重跑 `R-04-E` 矩阵，覆盖 DDL 负向约束、多轮并发、锁超时、指针修复、SQLSTATE、catalog 与执行计划。
- `I-04` 未通过时，可以继续修复代码，但不得宣称 PostgreSQL 适配器完成，也不得进入稳定发布或通过消费者候选合同。

当前状态（2026-07-30）：三个 PostgreSQL 包、迁移、`CheckSchema`、编译夹具和 API 快照已经实现；仓库内 `I-04` 已在 PostgreSQL 16.12 上通过。受保护 CI 证明仍依赖 `B-05`，因此本节实现任务完成但发布门禁尚未解除。

### 6. 形成候选并运行双消费者合同

- 先完成 `B-01B` 的 vanity 解析部署验收并绑定 `B-04` 和 `B-05`，再创建不可变 `v0.1.0-rc.N`。
- TMS、Parcel 分别对同一版本与 module checksum 运行其拥有的 `bento-contract`。
- 任一结果失败、超时、缺失或 checksum 不一致都阻断稳定 tag；框架不得获取消费者业务源码或完整 CI 权限。

## 兼容性制品

代码基线必须创建并纳入评审：

```text
api/
  packages.json
  snapshots/
    domain.apidiff
    repository.apidiff
    eventing.apidiff
    application.apidiff
    testkit.apidiff
    postgres.apidiff
    postgres-outbox.apidiff
    postgres-inbox.apidiff
  behavior/
    envelope-current.json
    envelope-v1.json
  changes/
    <from>--<to>.json
    <from>--<to>.apidiff.txt
compat/
  compile/
    core/
    postgres/
internal/
  compatibility/
  consumerproof/
  cmd/
    apisnapshot/
    candidatecheck/
    compatcheck/
    compatmanifest/
    dependencycheck/
    proofcheck/
```

首个 `v0.1.0` 没有上一发布版本，初始 snapshot 必须与公共符号 allowlist 对齐并由两个消费者代表确认。后续更新当前 snapshot 不能删除与上一发布版本比较的证据。

仓内候选前置门禁已经收敛为 `internal/cmd/candidatecheck`；首个 `v0.1.0-rc.1` 使用 `-initial-v0-1`，后续候选必须传入独立不可变旧 `api/` 基线。该命令要求真实 PostgreSQL DSN 并运行无缓存全量测试，但不解除 `B-01B` 剩余的线上解析验收以及 `B-04` 至 `B-06`。

双消费者最小证明已经固定为严格 JSON v1，并由 `internal/cmd/proofcheck` 校验预期 TMS/Parcel 提交、同一预发布 SemVer、module checksum、合同套件版本和两个 `PASS`。该内容校验不验证证明来源或授权，不能替代 `B-04`/`B-05`。

## ADR 候选

已按 ADR 三条件记录难以逆转的选择：独立共享框架、标准库核心与可选适配器分离、context 事务传播及严格模式、PostgreSQL 所有权与一致性、确定性 testkit、四层兼容性与双消费者发布治理，以及长期 module path 与 Git transport 解耦。精确接口、DDL 和测试矩阵仍由各设计合同维护，ADR 不复制易演进细节。
