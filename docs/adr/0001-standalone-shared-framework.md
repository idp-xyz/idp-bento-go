# ADR-0001：建设独立的共享 Go 框架

状态：已接受

日期：2026-07-29

## 背景

TMS 与 Parcel 都需要可复用的 DDD、事务、事件和持久化技术原语，但任何一个产品成为框架宿主都会把另一个产品的升级、所有权和发布节奏绑定到宿主。复制两套内核则会产生协议和修复分叉。

## 决定

将 `idp-bento-go` 建设为独立、业务无关、单独版本化的 Go module。TMS 与 Parcel 都是消费者，不是宿主；框架不拥有产品领域模型、业务数据、运行时或发布周期。

## 后果

- 两个产品可以独立升级并通过精确版本依赖共享修复。
- 框架需要独立治理、CI、发布和兼容性责任。
- 只有双消费者用例或批准的公司级技术需求才能扩大公共 API。

## 考虑过的替代方案

- 由 TMS 或 Parcel 托管共享内核：会使另一产品依赖宿主内部结构和发布时间。
- 在两个产品内分别复制：短期简单，但协议、迁移和安全修复必然分叉。
- 建设包含业务模型的共享平台：破坏限界上下文和数据所有权。
