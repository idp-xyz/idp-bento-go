# ADR-0004：框架拥有技术迁移，消费者拥有执行

状态：已接受

日期：2026-07-29

## 背景

Outbox/Inbox 技术表必须与框架实现版本一致，但 TMS 与 Parcel 拥有不同的数据库权限、业务迁移、维护窗口和私有化交付流程。由任一方单独复制或修改框架 SQL 会形成不可验证的分叉。

## 决定

框架发布不可变、带 ID 和 checksum 的技术迁移模板与受控渲染 API；消费者拥有迁移工具、执行顺序、凭据、审批、历史、备份和回退。应用启动只运行只读 `CheckSchema`，不得自动迁移或修复。

## 后果

- 框架可以保证技术 schema 与版本兼容，消费者仍控制生产变更。
- 框架和消费者都必须维护迁移兼容性合同与升级测试。
- 已发布迁移只能追加，不能改写；消费者不得复制后修改。

## 考虑过的替代方案

- 框架在应用启动时自动迁移：越过消费者的生产审批和最小权限边界。
- 消费者复制框架 SQL：会丢失 checksum、升级路径和修复一致性。
- 框架接管消费者完整迁移：会混入业务表并破坏产品所有权。
