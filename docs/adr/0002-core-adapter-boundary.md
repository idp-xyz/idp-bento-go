# ADR-0002：分离标准库核心与基础设施适配器

状态：已接受

日期：2026-07-29

## 背景

核心技术合同需要长期稳定，而数据库驱动、遥测和消息基础设施具有更快的演进速度。把它们放在同一依赖层会让消费者被迫承担不需要的依赖，并使公共边界随适配器变化漂移。

## 决定

`domain`、`repository` 和 `eventing` 只依赖 Go 标准库，`application` 只依赖标准库与公共核心，`testkit` 不进入生产依赖图。`postgres`、`postgres/outbox` 和 `postgres/inbox` 是隔离的实验性适配器，核心不得反向导入。

## 后果

- 核心合同可独立测试和演进，消费者只引入实际需要的基础设施。
- 适配器需要显式装配和额外的依赖方向门禁。
- 通用 ORM、宽泛 `common` 包和产品专属适配器不能进入核心。

## 考虑过的替代方案

- 单一宽泛框架包：导入简单，但职责、稳定性和依赖方向不可验证。
- 核心直接依赖 pgx/OpenTelemetry SDK：会把可选实现变成公共强依赖。
- 通过通用 ORM 隐藏数据库：无法表达已确认的事务、锁与 SQL 所有权。
